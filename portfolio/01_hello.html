Project Hello Quad

OpenGL / WebGL 2 / GLSL

Project Overview

This project establishes the foundational rendering pipeline for a cross-platform OpenGL demo framework targeting OpenGL 3.3, OpenGL ES 3.0, and WebGL 2. The goal was to implement core GPU resource management classes and produce an animated, interactive quad rendered with custom GLSL shaders. The quad responds to mouse input in real time and features smooth time-based scale and rotation animations.

Tasks Completed

  • IndexBuffer: Implemented a RAII GPU index buffer supporting unsigned int, unsigned short, and unsigned char index types with move semantics and proper GPU resource cleanup via GL::DeleteBuffers.
  • VertexBuffer: Implemented a RAII GPU vertex buffer supporting static allocation and partial data upload via GL::BufferSubData, with full move semantics.
  • VertexArray: Implemented a VAO wrapper that records interleaved vertex attribute layouts from a BufferLayout, supporting integer attributes, instancing divisors, and both indexed and non-indexed draw calls.
  • Texture: Implemented a 2D texture class supporting file and raw memory loading via stb_image, configurable filtering and wrapping modes, and multi-slot binding with GL::ActiveTexture.
  • Vertex Shader Animation: The quad scales smoothly between a minimum and maximum size using abs(sin(uTime)) and rotates with a -cos-driven angle that produces natural pause intervals at direction changes.
  • Fragment Shader Animation: Colors cycle between per-vertex colors and texture colors using a sin-based blend factor, with a mouse-proximity glow effect computed via smoothstep.
  • Mouse Interaction: The quad follows the mouse cursor in real time. Mouse pixel coordinates are converted to NDC using window::DisplayWidth and window::DisplayHeight from window/Environment.hpp, correctly accounting for the ImGui menu bar offset.
  • Custom Texture: Designed and painted a custom pixel-art texture for paint_me.png used as the quad's diffuse map.

Reflection

The most challenging aspect was accurately mapping mouse pixel coordinates to NDC space. ImGui's docked panels offset the usable render area from the full window size, so using raw window dimensions produced persistent misalignment. The solution was to rely on window::DisplayWidth and window::DisplayHeight, which reflect the actual OpenGL render region after subtracting the menu bar and docked panel areas.

Implementing the VAO with correct EBO association order was another key learning point. The index buffer must remain bound while the VAO is still bound, or the association is silently lost. This reinforced the importance of understanding OpenGL state machine ordering rather than treating bind and unbind calls as symmetric operations.
